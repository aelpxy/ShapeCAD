# 2. Write everything in Rust

Status: accepted

## Context

The requirement is a native application with no web stack, on Linux, Windows and
macOS. That eliminates Electron and Swift. The realistic field was C++ and Rust.

Under an earlier plan built on OpenCASCADE, C++ had a genuine advantage: every
mature geometry library is C++, and choosing Rust would have meant an FFI seam
across the hardest part of the system.

## Decision

Rust throughout, with no C++ component.

## Consequences

ADR 0001 removed the C++ gravity entirely. The tools for implicit modelling are
Rust-native: `wgpu` for GPU work, and `fidget` for JIT-compiled field evaluation.
and there is no comparable C++ stack. The FFI tax went to zero.

Secondary benefits, in order of how much they actually matter:

- One build system. `cargo build` with no CMake, no vcpkg, no system library
  hunt. For an open-source project this materially lowers the contribution bar.
- Safe aggressive threading, which field evaluation wants.
- Memory safety in a long-lived application juggling GPU buffers and a large
  mutable document graph.
- The compiler catches a real fraction of what AI agents get wrong before
  runtime. Worth having, but routinely oversold.

Costs accepted:

- A smaller contributor pool. People who have worked on FreeCAD, OpenSCAD or
  Blender are C++ programmers.
- An immature GUI ecosystem; this is the weakest part of the bet.
- Graph-shaped data needs arenas rather than `Rc<RefCell<_>>`.

Explicitly not a reason: performance. C++ is equally fast.
